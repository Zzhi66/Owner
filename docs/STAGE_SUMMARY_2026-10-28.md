# Owner 项目阶段总结

日期：2026-10-28。总结范围：从界面原型、P0–P4 第一版交付，到本轮导航体验优化。

## 1. 当前结论

Owner 已从个人工作台的界面原型，发展为可实际录入、查看、管理和备份个人信息的浏览器应用。当前采用本地优先方式，保留中文贾维斯 HUD 和右侧 Agent 悬浮工作窗。

第一版 P0–P4 已发布为 [v1.0.0](https://github.com/Zzhi66/Owner/releases/tag/v1.0.0)，对应提交 `f16854f`。其后的导航优化已在 `21a8db2` 完成实现与本地验收，本轮与阶段总结一起同步。包版本仍为 1.0.0，导航改进尚未单独发布新版本；v1.0.0 标签继续保留原始交付内容。

当前适合开始在固定浏览器和地址中持续使用、积累记录与反馈。真实数据同步和真实 Agent 属于下一阶段，不能将当前本地规则演示视为模型能力。

## 3. 已具备的用户能力

### 信息呈现

总览保持「资产 → 今日待办 / 日程 → 个人近况」的顺序。近况包含身体、饮食、学习 / 工作和习惯，支持点击、触屏、拖动与键盘排序。心情和精力归入身体，阶段目标归入投入，完整历史进入领域详情。

| 领域 | 当前能力 |
| --- | --- |
| 身体与心情 | 睡眠、体重、步数、心情、精力；按日期查看及趋势统计 |
| 饮食 | 餐食内容、餐次和估算热量；支持缺失热量，保留零值语义 |
| 学习 / 工作 | 专注分钟、项目统计、阶段目标、下一步加入待办并去重 |
| 习惯 | 自定义、改名、停用 / 启用、打卡；按历史计划计算完成率和热力图 |
| 资产 | 人民币账户、资产与负债、隐藏金额、账户快照和估值历史 |
| 待办与日程 | 快速添加、撤销、完成、编辑；单次全天或带本地时间的日程 |
| 随手记 | 快速记录、查看、编辑和删除恢复 |

领域详情支持近 7 / 30 天，图表配有单位、日期范围、来源、摘要和可键盘展开的数据表。缺失记录不补零，净资产估值不冒充交易流水，隐藏金额会同步隐藏相关资产图表和数值表。

### 数据管理

- 正式记录使用设备本地日期；示例和原型空间固定参考 2026-10-14。不同空间独立统计。
- 旧 localStorage 先只读检查、预览再复制；支持按领域和日期选择旧记录，保留原文和来源。
- 新增、编辑与删除通过校验及事务提交；失败保留草稿，过期编辑不能静默覆盖其他页面的修改。
- 普通删除进入回收站。完整备份支持独立恢复副本、同类型空间替换与恢复点回退，替换 / 回退前保护当前内容。
- 数据库为 `owner.workbench.v2`、schema 3；完整备份为 `owner-workbench-backup` v1，上限 20 MiB。本轮没有结构迁移。

浏览器、协议、域名和端口决定数据来源。建议持续使用 `http://127.0.0.1:4173`；更换来源前先完整备份。具体操作见 [数据口径与恢复指南](DATA_AND_RECOVERY.md)。

### Agent 与导航体验

Agent 包含对话、任务、产物和 Markdown 导出。运行中收起后仍可完成，刷新后过期任务标为中断；输出明确标注本地规则演示。尚未连接模型、设备或外部执行工具。

本轮导航改进包括：

- 160ms 选中光条、200ms 内容过渡和 120ms 标题过渡，外壳与 Agent 保持稳定。
- 按空间和模块记住当前标签会话的滚动位置；再次进入及前进后退时恢复，刷新后重新开始。
- 连续点击响应最后选择，取消旧动效；预加载详情模块，慢加载给出反馈，失败后可重试。
- 原生 View Transitions 不可用时降级为轻量淡入；减少动态效果时直接切换并取消运行中的动画。
- 导航上下文改为会话状态，切换页面不再与个人记录保存争抢数据库写入；Agent 草稿保留。


`dist/` 继续作为受保护的原型源码纳入 Git。构建核对原型文件树及 SHA-256，审计生产模式、首屏图表隔离、本地资源及每个 JS 分包 ≤500 kB。当前构建为 19 个 JS 分包；这些门槛用于发现回归，不等同于长期性能基准。

## 6. 当前边界与下一阶段建议

当前主要数据来源仍是手动录入和旧记录导入，最初设想的自动同步尚未实现。Agent 仍是规则演示；单次日程没有重复规则和系统通知；没有跨设备账户、Three.js、桌面安装包或 PWA 离线冷启动。已加载页面的本地操作验证不能代替离线启动能力，长时间使用与海量数据性能仍需积累证据。

建议按以下顺序推进；这是下一阶段建议，不代表已开始实施：

1. **先积累真实使用反馈。** 固定地址持续记录，确认最常用的指标、录入路径和易遗漏字段，定期完成一次备份 / 独立副本恢复演练。
2. **为 P5 选定一个真实数据来源。** 明确数据范围、身份标识、同步方向、冲突与失败重试，先做好一个可验证的接入闭环。
3. **接入只读 Agent。** 确定模型运行方式和凭据边界，先支持可追溯的查询、总结、取消任务及产物；随后再设计带预览、确认和适用时可撤销的写入动作。
4. **按使用需求决定 P6 / P7。** 3D 先局部增强并保留 SVG 降级；确定桌面需求后再引入 Tauri / SQLite 和迁移流程。
