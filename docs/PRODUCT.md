# 产品基线

## 目标

独立的个人工作台，先统一个人信息，再逐步接入 Agent。数据来源采用混合方式：可以同步的同步，其余手动补充。当前阶段是本地界面原型，运行与打包方式尚未最终决定。

## 已确认的信息结构

| 区域 | 内容与用途 |
| --- | --- |
| 顶部控制台 | 页面标题、快速记录、明确的日期口径 |
| 资产概览 | 净资产、总资产、负债、变化；允许隐藏金额 |
| 今日行动 | 今日及此前未完成待办、近期日程与重要日期 |
| 身体状况 | 睡眠、体重、活动量、每日心情与精力 |
| 饮食 | 三餐记录、餐食内容与营养估值 |
| 学习 / 工作 | 专注投入、阶段目标、下一步行动 |
| 习惯 | 自设习惯、打卡与历史趋势 |
| Agent | 右侧点击展开的悬浮工作窗，含对话、任务与产物 |

总览展示摘要，历史与完整数据进入领域详情。资产始终位于近况上方，近况卡片支持用户排序。新增内容优先整合进已有领域，避免总览不断堆叠卡片。

## 视觉与交互

- 深蓝底色、青色 HUD 线条、琥珀色提示、环形核心装饰。
- 中文内容为主，英文作为辅助标签；装饰不代表真实系统状态或计算分数。
- 保持数字可读、键盘焦点可见、窄屏不横向溢出。
- 桌面近况双列，手机单列；Agent 不长期占据半屏。

## 已有能力与限制

- 已有手动记录、待办、打卡、日程完成 / 恢复、目标管理、图表、JSON 导出。
- 阶段目标最多 3 个；下一步可加入待办，同一未完成行动去重。
- 日程为单次日期，尚无重复规则与系统通知。
- 初始数据为示例，今天相对固定日期 2026-10-14；不是实时个人监测。
- 数据只保存在当前浏览器 localStorage，未实现正式数据库及多端同步。
- Agent 通过本地规则生成演示回复，没有接入模型或执行外部任务。

## 第一阶段正式开发验收目标

1. 正式记录与示例模式清楚分开，日期和跨天统计正确。
2. 各领域数据结构、校验与存储边界明确，可迁移、可备份、可恢复。
3. 核心记录可增删改查，刷新后保留，异常时不丢失原始数据。
4. 保持当前视觉和交互基线，再逐步增加数据同步与真实 Agent。
